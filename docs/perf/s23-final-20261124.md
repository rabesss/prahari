# Galaxy S23 measurement, 24 November 2026

The physical phone was a **Samsung Galaxy S23 SM-S911B**,
Snapdragon **SM8550**, Android 14, `arm64-v8a`. The measurement was taken on
24 November 2026, approximately 10:00–10:15 IST. The installed arm64 APK was
produced by the successful Android CI run 45325313415 (in the private development repository)
from commit `b3d61f973cc71598d05360be6fa1218e704f1bbd` (post-rewrite SHA; the CI run page shows pre-rewrite commit `fc62d117`, which has the same `android/` and `candidates/` files but a different overall tree); its SHA-256 was
`ac5f7a8a5507726a189b953f8c562995e10984aa95dd7373e99196e1bf2bdd0a`.
The installed package declared no Android `INTERNET` permission. The Llama PTE
and tokenizer matched their pinned SHA-256 values on the device.

**Scope limitation:** main advanced during the session to
`c5689ddaa697f0cd7775e99c9808e1e610fce54f`. Those commits changed two Python
files copied into Android builds (`triage/callguard.py` and `triage/cli.py`).
This capture is evidence for the APK at `b3d61f97`, not a measurement of an APK
built from `c5689dda` or a later commit. The old 1.20 s / 43 tok/s figures are
from a different, earlier APK; do not present either result as a measurement
of the later build without another physical-device run.

## Method and limitations

The runbook's first attempt found the phone locked after the 520.8-second model
transfer and skipped all ten samples. After waking and unlocking the phone, the
unmodified `adb_bench.py run` stage completed six checks. Three off-screen
chips were missed because the runner expected accessibility labels ending in
`SMS sample`, `Link sample` or `Network sample`, while this APK exposed labels
ending in `SMS`, `Link` or `Network`. A temporary copy of the runner changed
only the sample-row regular expression from `(?:SMS|Link|Network) sample` to
`(?:SMS|Link|Network)(?: sample)?`; it then completed nine checks. The original
runner in the repository was not changed. Both runs used the runbook's 500 ms
memory polling, 8-second settle and 60-second per-check timeout.

The lookalike-link stats header remained pending after 60 seconds in **both**
runs. Its screenshots and partial detector/total fields are retained but are
not counted as completed Llama timing results. The adjusted run's overall
completed-check median is 2.90 s and 22.6 tok/s, across nine different checks;
it is not a ten-check result. Device data, raw JSON and CSV, UI XML, screenshots,
memory snapshots, battery data and hashes are in
[`evidence/galaxy-s23-20261124/`](../../evidence/galaxy-s23-20261124/).

The final-source Android tree contains `CallGuardPreview.kt`, but no Android
code calls `CallGuardPreview` or exposes its dialog. Consequently no Call Guard
clip was captured; the presence of the standalone implementation does not
establish that the feature is accessible in the tested APK.

## Device clips

The [video directory](../../evidence/galaxy-s23-20261124/video/) contains
real-time screen recordings of synthetic parcel scam SMS, SBI debit alert,
UPI refund link, and Hindi KYC scam checks with airplane mode on. The Hindi
clip switches the result screen to Hindi. The parcel example's displayed
classification describes a customs threat; review the displayed advice before
using it in the final demo.

Original recordings are retained in `video/original/`. The original SBI and
UPI clips are 7.47 s and 8.80 s because the recorder stopped emitting frames
when the display was static. The two files at the top of `video/` extend only
the final still frame to approximately 12 s; their action sequences are not
sped up or slowed down. Original parcel and Hindi clips are 11.68 s and 13.74 s.
All inputs are synthetic. `video/sha256.txt` lists hashes for each file.
