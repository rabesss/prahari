# Galaxy S23 gating measurement — 24 November 2026

The measured APK was the arm64 debug artifact from successful
[Android CI run 45398563324](https://github.com/rabesss/arm-bharat-ai-soc/actions/runs/45398563324),
built from main commit **`5b59ee2fcaaa2b6153f9a302abb76a1aac5dd317`**. Its
SHA-256 was `88f6a53285c04ef8e0fb7766b05da716dbdc22a4b11112e731b70165e3d07862`.
The physical Samsung Remote Test Lab phone was **Galaxy S23 SM-S911B**,
**SM8550**, Android 14, `arm64-v8a`, Noida, 24 November 2026 IST. The installed
app declared no `INTERNET` permission; the PTE and tokenizer matched their pinned
hashes on the phone. KV prefix reuse remained disabled: the app resets context
around each generation.

## Results

The benchmark used six built-in visible samples in each of two passes: cold
KYC, two warm KYC checks, bill reminder, official link and lookalike link.
The `all` pass used Llama for every item; `flagged-only` skipped it for both
benign items. The model was preloaded before each pass; the totals below do not
include initial preload. Battery temperature was **41.7°C** on first connection,
**43.2°C** before the first successful check and **45.1°C** after the last;
the preferred below-38°C starting temperature was not achieved.

| Measure | Llama on all items | Flagged-only gating |
| --- | ---: | ---: |
| Completed terminal checks, including labelled detector fallback | 6 | 6 |
| Llama skipped | 0 / 6 | 2 / 6 (33.3%) |
| Median / p90 total, all six terminal outcomes | 1.984 / 3.977 s | 2.611 / 5.252 s |
| Median / p90 total, only `ok` rows | 1.914 / 2.593 s (n=5) | 2.573 / 3.522 s (n=5) |
| Warm KYC median / p90 | 1.857 / 1.873 s (n=2) | 2.611 / 2.641 s (n=2) |
| Warm KYC median TTFT / prefill | 879 / 879 ms | 1,275 / 1,275 ms |
| Warm KYC median prefill / decode speed | 165.0 / 32.5 tok/s | 113.8 / 23.9 tok/s |
| Benign gated total | — | 0.186 s bill; 0.312 s official link |

P90 uses linear interpolation at `(n - 1) * 0.9`; these six-item and two-item
samples are too small to establish a stable tail latency. The mixed-workload
figures include cold process-start and lookalike fallback outcomes and should
not be presented as a production traffic distribution. The gated skip fraction
is for this synthetic six-item workload, not an estimate of real traffic.

The [per-check table](evidence/galaxy-s23-gating-20261124/retry/summary.md)
and [raw JSON](evidence/galaxy-s23-gating-20261124/retry/results.json) retain
detector time, prompt tokens, prefill time and speed, TTFT, decode speed, total
time and PSS. For example, warm KYC in the `all` pass measured detector
15.848 / 12.386 ms, prefill 879 / 879 ms and decode 31.927 / 32.980 tok/s.
The two gated warm checks measured detector 15.944 / 15.911 ms, prefill
1,299 / 1,251 ms and decode 25.045 / 22.709 tok/s. Exact standalone decode
durations are not emitted by this build. The generation wall times were
1,756 / 1,728 ms in `all` and 2,417 / 2,484 ms in `flagged-only`; these include
prefill and must not be labelled pure decode time. `prahari-perf.jsonl` retains
those values and the full verdict-call times (50.380 / 36.338 ms and
48.781 / 48.313 ms, respectively).
The prefill interval includes tokenization, as documented by the harness.

The lookalike sample reached a terminal result in both passes: **5.001 s**
and **6.399 s**. In both, Llama ran but no reply passed validation, and the UI
showed a labelled detector-text fallback. The harness marks these rows
`detector-fallback` and excludes them from its successful Llama aggregates;
the displayed per-generation prefill/decode stats refer to the last attempt,
while total time includes the retries. This confirms completion and fallback,
not successful generation of a grounded Llama explanation.

Peak memory during the retry was **1,795.3 MiB PSS** and **1,907.9 MiB RSS**,
the highest samples from 500 ms polling across all checks; shorter spikes may
be missed. The post-run snapshot was 1,741.9 MiB total PSS and 1,847.9 MiB total
RSS.

## Comparison and caveats

The 23 November S23 capture reported about **1.20 s and 43 tok/s** on a
different earlier APK. This run's warm `all` KYC median was **1.857 s and
32.5 tok/s**. Both identify as SM-S911B / SM8550, but were different RTL
reservations and builds. The battery was already warm in this run and rose
during testing, and the app and prompt changed; thermal state, device variation
and build differences are plausible contributors, not proven causes. The
flagged-only pass always ran second at a higher recorded temperature, so its
slower flagged KYC measurements do not isolate the effect of gating.

The first, unmodified harness attempt produced no valid timing rows. The new
sender field placed the Check button beneath the Android navigation bar, so the
tap left the app; the RDB bridge also disconnected. After reconnecting the same
phone and rechecking both device model hashes, the retry used a temporary copy
of the runner with one additional vertical swipe to expose the Check button.
The precise [automation adjustment](evidence/galaxy-s23-gating-20261124/scroll-adjustment.patch),
[initial failed attempt](evidence/galaxy-s23-gating-20261124/results/) and
[retry artifacts](evidence/galaxy-s23-gating-20261124/retry/) are retained.
The app and measured APK were unchanged. The script's exit code was 2 because
both fallback rows are treated as incomplete for Llama aggregation.

The APK and model were installed and staged on the phone, then uninstalled and
removed; airplane mode was disabled and the screen timeout restored. Samsung's
Return button was disabled, so the reservation expired naturally; its reservation
page then showed no active devices. The Samsung account remained signed in.
